## Best AI use cases from this batch

### 1) AI-assisted directory businesses
- Use Claude Code + crawler/scraper stack to turn raw niche data into a monetizable directory.
- Best niches are boring, high-intent, price-opaque, and local.
- Strong playbook:
  - scrape data
  - remove obvious junk
  - classify relevant businesses/sites
  - enrich with decision-making fields (pricing, amenities, service area, inventory, images)
  - publish SEO pages fast
  - monetize via lead gen, vertical SaaS, premium listings, ads, or adjacent services
- High-signal niches are where people need to compare options, not just discover them.

### 2) Personal AI operator / Clawbot as async employee
- Morning brief / overnight worker is a killer primitive.
- Useful recurring jobs:
  - trend monitoring
  - competitor monitoring
  - building small internal tools while you sleep
  - content repurposing
  - surfacing high-signal opportunities from X / news / email
- Best framing: not "chatbot", but "proactive employee with context + memory + permissions".

### 3) Agent builds internal workflow tools for itself
- Strong pattern: ask the agent to improve its own workflow.
- Example outputs:
  - project dashboard / mission control
  - tracking board for tasks completed by the agent
  - PR creation instead of auto-pushing to prod
  - self-generated skills based on observed repetitive work
- This matters for Clawbot because self-scaffolding is one of the highest leverage loops.

### 4) Marketing machine built from code + MCPs
- Repeated theme: use AI to connect trend discovery, content generation, publishing, and product updates.
- Valuable because it collapses idea -> prototype -> content -> distribution into one loop.

## Patterns that work
- Niche and specific beats broad and generic.
- Data quality is the moat; the website is the wrapper.
- AI works best when asked to do one enrichment pass at a time.
- Human review should sit at high-risk steps (publishing, payments, prod deploys).
- Give the agent rich context about you/business early; that increases proactive usefulness.
- Use strongest models for reasoning/planning; cheaper models can be the "muscle" for execution.
- In local SEO / local services, narrow structured pages still have real value even in an AI-search world.

## What does not work / pitfalls
- Trying to enrich too many fields in one pass lowers quality.
- Low-trust directories with thin AI content and no real differentiating data are weak.
- Giving an agent dangerous permissions too early is reckless.
- Generic horizontal directories or horizontal search products get crushed faster than niche, decision-stage products.
- If cash is needed in <6 months, slow SEO-first plays may be the wrong business model.

## Practical rules
- Build around save time / save money / make money.
- Identify the decision-making fields users actually care about before enriching data.
- Treat image scraping as legally risky unless rights are clear.
- Use PRs and drafts by default; do not auto-push important changes.
- Ask the agent what else it could do for you; unknown-unknown discovery is part of the value.

## What applies to Clawbot
- Clawbot should be treated like an employee with:
  - context files
  - recurring briefs
  - limited permissions
  - review checkpoints
- Strong fit for:
  - opportunity scouting
  - small workflow tools
  - self-updating process improvements
  - competitive research
- Weak fit for:
  - fully autonomous high-risk posting/trading/purchases without guardrails
